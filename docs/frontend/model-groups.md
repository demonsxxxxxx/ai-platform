# 模型分组前端接入

模型管理页分为“供应商配置”和“模型组分配”：供应商维护连接与模型目录，模型组选择模型、指定默认模型并分配成员。“模型组分配”使用后端 `/api/ai/admin/model-groups` 原子接口：

- `GET /api/ai/admin/model-groups` 和 `GET /{group_id}` 读取管理投影；
- `POST /api/ai/admin/model-groups`、`PATCH /{group_id}`、`POST /{group_id}/retire` 管理业务组；
- `PUT /{group_id}/models` 与 `PUT /{group_id}/members` 按 revision 一次替换组模型/成员；模型配置页的批量添加/替换/移出使用 `POST /api/ai/admin/model-groups/models/batch`，先 `preview:true` 校验 before/after，再用同一组 revision 的 `preview:false` 原子提交；409 保留选中草稿并要求刷新详情。
- `GET/PUT /api/ai/admin/users/{user_id}/model-groups` 通过单选一次替换用户唯一业务组，清空成员必须明确确认回默认组；
- `/api/ai/models/groups` 和 `/api/agent/models/available?group_id=...` 是普通用户公开投影，不包含管理备注、权重、成员或存储信息。

模型可同时加入普通默认组和任意业务组。每个用户只归属一个组，未分配业务组时自动归属普通默认组。用户分组抽屉使用单选，组成员编辑新增人员会转移其旧归属，不再提供主组按钮。聊天初始化当前唯一归属组及其默认模型，用户可以再手动切换到同组其他模型。普通默认组仅禁止普通聊天，专家入口仍可使用；所有聊天入口均不显示组选择器；默认模型不可用时提示用户手动选择，不自动替换或跨组回退。失去组或模型资格时前端清空模型并阻止发送，服务端仍是最终准入 authority。新会话和续聊提交具体 `group_id`、`selection_mode=explicit`、`model_id`/`model`，不能用客户端场景绕过服务端授权。

## 多供应商配置与删除

模型配置页默认全部收起，每家供应商占一行，名称旁显示模型数，删除与展开箭头位于右侧；点击展开连接及模型编辑，点击另一行切换，再次点击可收起。新增供应商后主动展开新建项以填写连接；删除后不自动展开其它供应商。每家分别维护 API 地址、Key 和模型目录。新增供应商后填写连接、获取模型，调整参数再保存；测试连接和获取目录仍不直接发布。切换管理对象不切换用户的组或默认模型；有未保存修改时先确认放弃，正在保存时不可切换。Key 不回显，也不会随供应商切换带到另一家。

同名上游模型在不同供应商拥有独立平台 ID，聊天菜单和组模型选择显示供应商以便区分；组可以授权多家模型，默认模型按 ID 绑定，不按同名值猜测。刷新或发布一家不改变另一家的模型、Key 或可用性。

供应商行显示连接是否已保存、目录模型总数、启用数与上游缺失数；这些是已保存配置的摘要，不能证明当前连接测试成功，启用数与缺失数可以重叠。目录分别展示“已保存”“待保存候选”“待保存修改”与上游发现状态。获取上游目录保留已有缺失模型，显示新增候选和缺失数量；仅缺失状态变化也形成待保存草稿。供应商配置有草稿时，先保存再执行该页的组模型分配，组编辑使用已保存的目录。

组模型编辑可按名称、上游 ID、供应商搜索，并按供应商 ID 筛选；筛选不改变已加入模型、展示顺序或默认选择。同名供应商以身份补充区分。已加入项显示供应商及目录停用、上游缺失、组内停用状态；目录未返回的历史关联保留原名称与 ID，并标记目录中不可用。当前默认模型被移除或组内停用时，保存前要求显式选择一个启用的组内模型；空组仍可保存。空目录、全部已加入和无匹配结果分别展示。

“删除供应商”先展示模型、关联分组、默认模型和未完成任务数量。有引用则需先在组管理中移出并改好默认模型、等待任务结束；没有引用才明确确认删除。正常目录不再显示已删除配置，历史会话、用量、Run/Attempt 不改。

升级时原连接及累计模型迁入“默认供应商”。此前换 Key 遗留的旧模型可用“清理上游已移除模型”删除；预览显示可清理数量及保留项的模型名、分组、默认模型和未完成任务引用；仅清理无引用条目，保留被引用项、当前连接及可用模型，不因一个引用阻断整批。分组编辑中，上游缺失模型仍显示原关联并标注缺失，取消勾选并保存可显式移除。分组名仅展示当前租户的引用，其它租户只显示引用数量。未来再次发现这些模型时可以重新配置。不会根据旧 Key 自动拆分供应商，也不会自动删除真实配置。

## 按组织架构选人

业务组成员页的“添加成员”打开双栏弹窗：左侧组织树，右侧员工名单；底部保留跨部门已选人员、移除、清空、取消和确认。部门节点显示名称，完整路径作为可访问名称与悬停提示。选择部门仅列直属员工，不自动包含子部门。标题副说明、重复部门人数/直属人员说明行和底部权限提示不再显示；员工行保留姓名、工号和已解析的部门路径。

搜索框按全公司姓名或工号搜索，不受左侧部门限制；清空搜索回到原部门。无搜索时“全选本部门”选择该部门完整直属员工；搜索时“全选搜索结果”只操作全部匹配人员。完整读取当前范围所有分页后才启用勾选，避免将已加载页误当全部人员；右侧复用既有 Virtuoso 虚拟列表，只渲染可视行。任一分页失败或目录身份不一致时禁止部分批量选择，并允许重试。全选、半选、逐个取消及范围切换均保留其他部门的选择。确认只更新组编辑草稿，最终保存仍走原 revision 原子接口和迁组/回默认组确认；取消或 Escape 放弃弹窗内变动并返回焦点，保留外层抽屉草稿。

复用管理员纯部门目录与 `/api/ai/admin/company-employees?department_id=...`。后者从同源 DingUser 的 `departId` 分号列表按精确部门 ID 筛选，只投影姓名、工号和经校验的 `department_ids`，不下发手机号、邮箱或原始员工对象。前端按纯目录匹配部门名称和路径；缺失或含歧义的部门关系不按名称猜测，员工仍可通过全公司搜索找到。部门选择和批量选择都只添加具体人员，不写部门授权或未来入职人员规则。组织/员工目录故障有明确重试入口；切换查询、关闭或禁用弹窗取消旧请求，迟到响应不覆盖新范围，无本地登录记录回退。

## 停用与删除

业务组停用保留成员和模型，可重新启用。删除只保留一项操作：弹窗显示成员、模型和未完成任务数量；有未完成任务时禁止提交。成员非空时必须选择全部转入另一个有效业务组，或显式选择回普通默认组并失去普通聊天资格；空组仅需确认。提交同时携带源组和迁入组 revision；失败保留弹窗，不自动重选目标。

删除由后端一次事务处理成员去向、模型关联和逻辑删除。组从正常列表隐藏，历史 Run/Attempt 保留；不删除模型，也不影响其他组的模型关联。无需先手动清空成员/模型，不再提供“停用并归档”或物理删除动作。旧 `/retire` 请求字段仅保留调用兼容，同样不能绕过成员选择。普通默认组不可停用或删除。

## 无需重登录刷新

`ModelCatalogProvider.refreshModels` 每次先重新获取公开组授权，再读取当前组模型。打开模型菜单（含 `/model` 和 slash 菜单）、可见窗口 focus/回前台、管理员发布成功及同页组变更均复用此入口；不轮询。普通并发合并，发布强制替代旧请求。有效组/模型、草稿和已打开菜单保留；组或模型被撤销时清空并提示明确重选，不自动跳组或模型。空组/空模型仍可打开菜单恢复；临时网络错误保留同账号旧数据，401/403 清空授权投影。账号、租户、组切换和卸载通过 abort/owner generation 隔离迟到结果。服务端最终准入和已有 Run 冻结不变。

## 退役库存

旧内嵌 `GroupMemberEditor` 单列 Popover、部门下拉框、手动“加载更多”及其说明文案已由 `ModelGroupMemberPicker` 双栏 Modal 替代，不留兼容选人入口。部门权限编辑器和用户唯一组抽屉不属于本次替换。`ModelGroupManagement.mounted.test.tsx` 保留原保存/迁组语义回归，`ModelGroupMemberPicker.mounted.test.tsx` 覆盖跨页全选、全公司搜索、半选、取消和失败重试；现有 route-layout smoke 更新组织树、批量选择及 Escape/焦点选择器。管理员员工 API 仅增加部门 ID 字段，原姓名/工号、查询与准入边界保持兼容。目录列表在单个服务实例内复用 60 秒已校验快照，并返回跨实例稳定的 `snapshot_id`；分页发现该标识或人数变化时拒绝混合结果。缓存只用于选人展示，保存时的 `validate_grants` 始终直接读取当前上游身份，不能用列表缓存授权。

旧“用户重新加载聊天页面后获取最新列表”提示和仅登录时加载目录的路径已由上述刷新入口替代；无新增逐模型 ACL 兼容路径。

旧 `ModelUserAccess` 逐模型员工 ACL 控件及其 mounted test 已删除。`modelAdminApi.publish` 不再发送 `is_default`、`access_mode` 或 `allowed_user_ids`；这些字段属于后端迁移只读输入，分组授权只通过上述分组接口完成。保留 `agentProfile` 的 `allowed_user_ids` 是专家发布的独立产品契约，不是模型目录 ACL。

模型目录发布测试覆盖旧字段缺席；分组 mounted test 覆盖目录加载、创建、drawer、模型/成员保存和原子请求形状。实际浏览器页面与真实后端联调由父owner验收。
