# LobeHub 风格与页面视觉约束

## 采用 Lobe UI，以 LobeHub 工作区作为视觉参考

通用 React UI 主库确定为 `@lobehub/ui`，版本、公开入口与交互归属遵守 [Lobe UI 接入合同](lobe-ui-adoption.md)。页面视觉以 LobeHub 的应用工作区为参考：中性黑白灰、轻量导航、弱边界、清楚的内容层级，颜色主要来自专家头像与必要的状态。

本文拥有页面视觉约束。下述尺寸和颜色是可执行的样稿基线，具体效果待用户验收；不能把组件接入、自动化检查或样稿完成写成全站视觉验收通过。后续页面调整以验收后的基线为准。

## 从官方界面提炼的方向

| 官方界面中可观察的做法 | 本项目采用的规则 |
| --- | --- |
| 导航与主内容通过细微底色区别，选中项使用低对比填充 | 使用一条轻量侧栏；文字左对齐、图标起点一致，不给每个导航项加卡片边框 |
| 黑白灰承担主要交互和内容，头像提供色彩 | 主按钮浅色模式黑底白字、深色模式浅底深字；不并行维护青绿、蓝色与黑白三套主色 |
| 输入器和真正独立的内容块有圆角；普通正文不层层包卡片 | 容器表达真实分组；禁止仅为装饰增加外卡片套内卡片 |
| 细线、轻背景多于重阴影 | 默认无阴影；只给浮层及输入器少量阴影；不使用大面积渐变和发光边框 |
| 图标紧凑、次要动作安静，主任务有足够留白 | 一屏一个主要操作重心；统计和解释不能把列表、输入或上传推到很下方 |
| 深色模式是完整的中性色系统 | 背景、正文、控件和 Portal 一起切换；禁止浅色业务背景配深色库控件 |

参考来源：

- [LobeHub 官方产品页](https://lobehub.com/)
- [官方工作区浅色示意](https://lobehub.com/img/hub/images/home/overview-cao-light.webp)
- [官方工作区深色示意](https://lobehub.com/img/hub/images/home/overview-cao-dark.webp)
- [Lobe UI ThemeProvider](https://github.com/lobehub/lobe-ui/blob/a5f87e9367149dba06a8f476c6e0082ec2287d4d/src/ThemeProvider/ThemeProvider.tsx)

官方在线工作区需要登录，本基线依据公开的官方工作区图及组件合同提炼。这里的像素值是本项目的设计选择，不冒充上游精确规格。保留 AI Platform 的身份和业务用语，不复制 LobeHub 的品牌标识、文案或功能范围。

## 样稿的尺寸、颜色与排版基线

| 项目 | 基线 |
| --- | --- |
| 浅色 | 外壳 `#f7f7f7`，内容 `#ffffff`，弱背景 `#f5f5f5`，正文 `#202020`，次要文字 `#707070`，边界 `#e8e8e8` |
| 深色 | 外壳 `#0b0b0b`，内容 `#111111`，弱背景 `#1c1c1c`，正文 `#ededed`，次要文字 `#a3a3a3`，边界 `#2b2b2b` |
| 页面字体 | 复用项目系统无衬线字体，显式包含 Microsoft YaHei / PingFang SC 等中文回退，不额外请求外部字体；正文 14px，辅助 12px，页标题 26px，区块标题 16px；聊天正文 15px、行高约 1.8 |
| 间距 | 4px 基础节奏，主要使用 8 / 12 / 16 / 24 / 32px；桌面页面左右 32px，窄屏 16px |
| 外壳 | 桌面侧栏 224px，主区域细边框与 12px 圆角；顶栏 56px；窄屏侧栏收进库 Drawer，不永久占用一条 52px rail |
| 内容宽度 | 目录和管理内容约束最大 1200px；聊天正文与输入器对齐，最大 800px |
| 控件 | 普通控件采用库默认尺寸；普通表单约 36–40px，紧凑工具条约 32px；窄屏主要触控按钮至少 40px |
| 圆角 | 库普通控件保持 8px；独立内容块 12px；聊天输入器可用 16px；不让同一类控件各自选择圆角 |
| 图标 | 常规 16–20px；图标按钮使用 ActionIcon 或 Button 的 icon 合同，禁止固定窄宽度却保留文本按钮 padding |

颜色通过主题语义进入页面和控件；正式迁移时在现有主题 owner 中统一，不另建第二套偏好存储。样稿局部变量只用于隔离未验收的视觉方案，不是新增的生产主题平台。

## 三类页面遵守同一套层级

### 目录页：标题、查找、内容

公司导航、专家市场和插件市场以内容发现为主。标题和一句简洁说明后接搜索/筛选，下面直接进入内容列表。卡片最多一层主体边框；名称、能力说明、主要动作清晰，次要统计退后。分类、收藏、排序不各包一层大容器。

### 管理页：对象列表与必要操作

技能、MCP、模型、运行、用户、角色和记忆使用一致的页标题、工具条与数据密度。连接/治理摘要不压过主要列表。表格使用 Lobe Table，列宽和横向滚动由业务 owner 设置；不能用单字竖排适配窄屏。状态标签保持单行和图标完整，不挤压为竖排。

### 任务工作区：内容与输入优先

专家对话、SOP 和 Word 审核以当前任务为中心。聊天正文不整体套大卡片；用户消息可使用轻背景。正文、附件和输入器对齐。上传或任务输入应进入首屏，统计不抢占位置。会话历史按需展开，避免两条宽侧栏同时挤压主内容。

## 控件、布局与文案的职责

- Button、ActionIcon、Input、TextArea、Select、Tabs、Switch、Table、Drawer、Tooltip、Toast 使用 Lobe UI 的公开组件。不要用手写元素重新维护对应交互，也不要增加无业务职责的同名包装。
- 页面 CSS 只拥有布局、响应式、内容排版和真实业务分组。通过公开 `style/styles/classNames` 适配必要尺寸，不以全局 `button/input/svg` 覆盖修补库。
- 局部页面使用 CSS Modules 或明确 owner 前缀；不复用 `.panel-header` 等全局名字表达不相同的结构。
- 标题说明服务于当前用户的操作，不展示 SDK、环境变量名、内部投影合同和实现说明。管理员确需的诊断信息放到对应诊断区。
- 搜索、筛选、主题切换和弹层必须可用；没有实现的能力不伪装为可点击按钮。示例页面明确标记“样式预览 / 示例数据”。
- 可访问名称以实际 DOM 为准。当前高层 Switch 不透传 `aria-label`，使用显式 `id` 与关联的真实 `label`；不能只检查 JSX 上写了属性。
- 不改变认证、权限、部门访问范围、Run/SSE、专业文档渲染及下载合同。视觉统一不能成为删除业务状态或安全控制的理由。

## 样稿入口与验收

开发入口为 `frontend/web/style-preview.html`，组件位于 `src/features/design-preview/`。它复用现有主题与 Lobe Provider，仅使用本地示例数据，不挂载认证、模型目录或业务 Provider。Vite 默认生产入口不包含该 HTML；不添加到生产路由 manifest。

样稿包含专家市场、模型管理和对话工作区。可切换页面、主题，搜索/筛选专家，收藏卡片，打开模型连接抽屉，编辑本地消息。交互只改变本地示例状态。

验收重点：

1. 侧栏、顶栏、页面留白和整体密度是否符合预期。
2. 专家卡片、管理表格、聊天正文与输入器是否属于同一套产品风格。
3. 浅色和深色的背景、正文、控件、状态、浮层是否完整一致。
4. 390px 下没有被裁切的正文/动作、逐字竖排表头或被挤没的图标；主动作容易找到。
5. 库交互可用：键盘焦点可见，抽屉 Escape 关闭并返回触发点。

可运行 `node scripts/lobe-style-preview-browser-smoke.mjs` 检查样稿交互与渲染。用户对样稿的视觉验收独立于脚本检查；批准后再把基线应用到实际页面，并移除被替换的旧样式。样稿保留到对应页面迁移完成，由前端视觉 owner 在届时退役。
