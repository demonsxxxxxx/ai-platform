# ADR 0015：任务自治与按影响分级的执行边界

- Status: accepted
- Date: 2026-09-29
- Owners: Agent Apps、Skills、Execution、Sandbox

## 决策

**任务内部充分自主，数据和外部操作边界明确，约束强度随实际影响变化。**

专家配置提供任务身份、指令、可用 Skills 和外部工具范围。Agent 自主决定是否调用、调用哪些以及如何组合；配置和加载不代表已经执行。产品从实际调用事件显示执行状态。

会话保存专家身份和原生上下文。每次新 Run 选择当前发布的专家及当前可运行的 Skill、依赖版本；在同一次受理中解析完整依赖图并保存最多 64 个包的执行快照。已受理 Run 的排队、重试和恢复使用原快照。会话创建时的版本只作来源记录，不阻止继续使用当前专家。

模型与思考强度保留用户在专家会话中的选择。专家入口不允许客户端自行扩大 Skill、文件或 MCP 权限。

## 边界与处理强度

| 行为 | 平台处理 |
| --- | --- |
| 任务规划、Skill 选择、工作区普通文件读写、搜索、可恢复的调用失败 | 自动执行；记录实际结果，允许 Agent 换方法继续 |
| 当前租户、用户、文件、专家、模型及工具授权 | 在跨权限边界处检查；历史上下文不授予权限 |
| 可选 MCP 不可用或撤权 | 仅移除该能力；执行集合为受理时已授权集合与当前可用集合的交集 |
| 外部写入结果不明、错误调用身份、缺失执行回执 | 保留不确定状态，阻止可能重复产生外部效果的自动重试 |
| 平台私有根目录和跨工作区路径 | 在实际读写和交付边界限制；普通目录的名字不构成权限边界 |

一次调用的已知失败与整轮任务失败分开。Skill 和平台判定的只读 MCP 可用合法失败回执结束该调用，随后继续任务。远端自报的 read-only 提示不能降低外部写入约束。最终成功需要正常 SDK 终态、有效调用记录和已持久化的完成信息；只有有效交付文件而没有正文也可成功。

## 单一路线

- 专家路由及执行选择只携带专家身份，不保留旧版本 URL 或客户端执行版本锁。
- 新 Run 不从旧包中嵌入的 dependency_manifests 回退解析依赖；Run 自身的历史快照仍是恢复依据。
- Skill 只安装到 SDK 原生 `.claude/skills` 目录，移除可配置的替代位置。
- 初始化器仅准备平台命名空间，不遍历、修补或阻断普通历史任务文件。
- MCP 独立并发发现并由各自任务持有连接；发现超时不限制健康连接的执行寿命。
- 同一提交使用原始规范化用户请求的一个指纹。重放先返回持久化结果，不重新根据当前工具集合计算身份。

## 验收与回退

回归覆盖新发布后继续会话、同 Run 固定快照、当前依赖变更、可选工具离线与撤权、失败后恢复、文件单独交付、调用回执异常和工作区边界。真实 SDK 与本地协议端点测试属于集成证据；生产模型、生产 MCP 和部署验收单独记录。

本次不迁移或删除历史业务数据。前后端需成套部署；回退采用整套应用版本回退，不添加并行兼容执行分支。

提交指纹协议切换后，旧请求正文不保证能再次 POST 重放。升级保留提交账本、Run、队列身份及浏览器已保存的提交标识；未确认提交通过现有 GET 查询与 retry-admission 恢复原任务，不重新提交正文或生成新任务。外部调用方也使用这两个恢复入口。
