# External Knowledge Requirement Traceability

## 1. Contract

Every row maps one atomic functional requirement to one implementation slice
and defines one atomic acceptance case. The case KAC-FR-R asserts exactly the
statement of requirement R in functional-requirements.md. This table is the
source acceptance manifest; scenario cases add integration, browser,
concurrency or migration coverage but do not replace the atomic case.

An Issue may split its owning slice, but it must update the row before code
merges. A requirement may not be marked covered by a test owned only by another
slice. Source-document validation fails when a requirement is missing,
duplicated, points to an unknown slice or has the wrong KAC-FR identity. The
KTRACE-62 required CI job for KADR-01 and every later slice additionally fails
when the candidate manifest differs from that slice's exact case set. KCI-56
aggregates the complete P0 set through packaged-image evidence, including the
required KINV-02 inventory manifest and KCI-56's own manifest; KACCEPT-58 owns
the external-runtime P0 requirement.
