# Run 故障诊断与字段治理 PRD

状态：实施中。本文定义完整产品目标；[技术方案](run-diagnostics-design.md)记录当前候选实现、迁移、删除项和剩余缺口。当前代码覆盖核心采集、持久化、管理查询、可读运行页面和有审计的单 Run 脱敏诊断包，不表示完整 PRD 已在正式环境验收。

## 1. 问题与目标

管理员已有运行管理页面，但执行失败经过异常包装、HTTP 传递、回调、终态归一化和页面投影后，可能只剩一个通用错误。部分诊断仍在执行租约中，管理页面却只读取 Run 结果；部分字段在进入持久化之前已经丢失。增加页面字段不能修复这类缺口。

使用者可能没有生产主机或 MCP 权限，也无法及时取得运维日志。产品需要支持：从一次失败定位到对应 Run、执行尝试和最早留存的异常，查看后续处理过程，并下载可交给研发分析的脱敏证据。

本次同时治理导致信息损失的覆盖、静默丢弃、重复映射、占位能力和失效兼容。每个实施批次均包含旧路径处置；新增能力和清理一起验收。

### 成功标准

1. 验收故障语料中的每个失败都能按 Run ID 找到记录，显示失败阶段、实际留存的异常、公共错误分类、后续处理及证据完整性。
2. 同一故障经过 HTTP、回调、Worker 和调和处理后，最早已留存的异常身份与阶段保持不变；新增异常形成关联观察。
3. 在应用与 PostgreSQL 可用、故障已被执行边界捕获的条件下，管理员可仅通过管理页面完成标准故障语料的初步分层定位与证据下载。
4. 每个被替换实现的生产调用、测试、前端选择器、配置和当前文档均有删除或保留依据。
5. 普通用户投影、身份隔离、终态权威和数据大小限制维持有效。

“最早留存的异常”不等于已经证明的根因。页面和诊断包必须保留这一区别。

## 2. 用户与使用流程

| 角色 | 需要完成的事 | 可见范围 |
| --- | --- | --- |
| 普通用户 | 知道任务失败，复制 Run ID 反馈 | 安全错误说明、已有任务内容及 Run ID |
| 现有 AI 管理员 | 定位 Run，按执行尝试检查故障链，下载诊断包 | 现有管理权限范围内的脱敏私有诊断 |
| 接收诊断包的研发 | 离线核对错误、处理过程、版本及字段缺失 | 下载包中明确列出的已脱敏内容 |
| 运维 | 处理主机、数据库、网络或应用完全不可用等情况 | 继续使用既有运维入口；本功能提供可关联的 ID |

### 典型流程

1. 用户在失败卡片复制 Run ID。提交尚未生成 Run 时仅提供请求 ID，不能伪造 Run。
2. 管理员进入现有运行管理页，按 Run ID 或会话定位，打开“诊断”。
3. 页面先显示业务状态和公共错误，再显示最早异常、发生阶段、最近处理、执行尝试和证据状态。
4. 管理员展开处理时间线，区分模型执行失败、派发/网络失败、回调失败、终态调和失败与展示失败。
5. 管理员下载本次 Run 的脱敏诊断包；研发直接读取结构化数据与说明文件。
6. 证据不足时，页面明确列出缺口和可关联 ID，不把通用错误文案当成根因。

## 3. 范围与优先级

| 优先级 | 范围 |
| --- | --- |
| P0 | 已创建 Run 的入队失败、执行派发、模型/工具失败、HTTP 异常、回调接收、终态调和和已有诊断的管理查询 |
| P0 | 最早异常保留、处理观察链、字段丢失说明、异步派发耗时持久化、授权脱敏下载、相关旧路径清理 |
| P0 | failed、cancelled、仍在运行但已出现异常的 Run；多 Attempt 按真实身份区分 |
| P1 | 生产采集覆盖率、证据缺失分布和排障耗时统计，接入现有观测入口 |
| 后续独立范围 | Run 创建之前的完整请求诊断、主机日志检索、全量分布式 Trace 平台、跨 Run 批量导出、自动根因分析 |

回调完全不能送达且 Executor 随后消失时，只能展示平台已记录的派发、超时与缺失情况。此次不承诺恢复 Executor 从未送出的原始异常。

## 4. 功能需求

| 编号 | 产品行为 | 验收条件 |
| --- | --- | --- |
| PRD-01 | 失败卡片提供可复制 Run ID；沿用安全错误分类 | 任意标准失败可用该 ID 在管理页定位；卡片不含私有异常 |
| PRD-02 | 诊断入口按权限和证据提供，状态不再固定限制为 failed | cancelled、running 中已记录的异常可查看；无证据时有明确状态 |
| PRD-03 | 显示最早留存异常的阶段、来源、类型、脱敏信息和发生时间 | 外层包装/终态转换不能覆盖这些值；未知值显示未知 |
| PRD-04 | 展示异常之后的包装、重试、回调、调和与终态处理 | 因果关联与时间排序分开；不能仅靠跨机器时间推断先后关系 |
| PRD-05 | 公共错误、执行结果、传输故障和展示异常分开展示 | 回调失败不能使页面声称模型失败；取消后出现异常不能改变取消事实 |
| PRD-06 | 显示 Run、Attempt、关联请求及可用的租约/回调身份 | 身份从服务端可信绑定取得；不同尝试的异常和耗时不能串接 |
| PRD-07 | 展示已测得的阶段耗时及其来源 | 缺失为未知，不能用 0 填补；异步派发后仍可读取已测耗时 |
| PRD-08 | 明确说明诊断缺失与压缩 | 区分未采集、历史格式、版本不支持、字段无效、已脱敏、已截断、已到保留期限 |
| PRD-09 | 显示执行及查询组件的实际版本来源 | 可用时显示 source commit / image digest / SDK 与契约版本；未提供则显示未知，不显示固定 POC 版本 |
| PRD-10 | 单 Run 脱敏诊断包下载 | 包含说明、结构化证据和缺失清单；同一快照可独立阅读；下载留审计 |
| PRD-11 | 刷新和断线重开仍能看到已持久化诊断 | 浏览器本地缓存、Executor 内存消失不影响已入库内容 |
| PRD-12 | 页面查看及下载不执行维护动作 | 打开页面、刷新、下载均不清理租约、不停止 Sandbox、不重跑任务 |
| PRD-13 | 数据范围与脱敏一致 | 非管理员拒绝访问；跨部署范围拒绝；管理员和导出也不能看到凭据或其他主体材料 |
| PRD-14 | 清理旧实现是功能交付的一部分 | 每批关联技术方案的删除项，提供调用迁移、失效断言和旧配置/文档处置证据 |

## 5. 管理页面信息结构

在现有 Run 详情内新增结构化诊断区域，替换当前单块 JSON 的主要交互。保留可折叠的脱敏结构化详情供研发使用。

| 区域 | 内容 |
| --- | --- |
| 概览 | 任务/会话标题、Agent、用户与工作区名称、Run 业务状态、公共错误、最早留存异常、最近处理、完整性状态 |
| 执行尝试 | 当前 Attempt 和有留存证据的其他 Attempt；清楚提示因预算未保留的详情 |
| 处理过程 | 阶段、来源、发生/接收时间、处理结果、因果关联、已测耗时 |
| 字段完整性 | 被截断、脱敏、拒绝或未采集的字段与原因；契约/策略版本 |
| 运行版本 | Run 派发时记录的执行组件版本，以及当前查询组件版本 |
| 导出 | “下载脱敏诊断包”、包内容说明、失败或不完整提示 |

列表和详情默认使用上述人类可读名称。Run、Session、Trace、Attempt、lease、callback 等完整技术标识保留搜索和关联能力，但只在次级摘要或可折叠“技术信息”中展示，不作为任务标题；缺少名称时才使用明确的未命名占位，不用 UUID 冒充名称。

显示示例（合成案例）：

```text
任务状态：失败                 公共错误：执行失败
最早留存异常：模型等待超时      阶段：model_wait
后续处理：Executor 包装 → HTTP 接收 → 终态调和
执行尝试：Attempt 2            证据：部分内容已截断
缺口：异常堆栈省略了中间内容，首尾摘要保留
```

页面可以说明“可能需要检查模型服务”，但首版不自动声称具体供应商故障或给出未经证实的根因。

## 6. 诊断包

首版为同步、单 Run、受大小限制的 ZIP；详情见技术方案。包内固定文件名：

- `manifest.json`：包版本、生成时间、快照身份、组件版本、内容摘要与缺失说明。
- `diagnostics.json`：脱敏的 Run/Attempt 关联、异常和处理过程、耗时及损失元数据。
- `README.txt`：如何理解公共错误与最早异常、字段单位、完整性和证据边界。

包中包含管理员定位所需的内部关联 ID；管理员下载即执行一次有审计的导出，产品不自动发送给他人。包不含原始提示词、文件正文、完整 SDK 载荷、凭据、内部连接地址或完整运行路径。人工复制或转交由持有人选择。

已成功记录的证据必须包含在预算允许的快照中。超出内容按明示规则压缩，并列出省略项，不能成功返回一个伪装完整的空包。

## 7. 质量、边界与目标

以下是拟定验收目标，不是当前性能声明。测试记录数据量、并发、机器和精确构建版本。

| 维度 | 要求 |
| --- | --- |
| 持久性 | 回调正常路径在同一数据库事务提交关联诊断与既有回执；Worker 正常路径在失败终态事务保存诊断。诊断专属构建/归一化/预算/写入失败经 savepoint 有界降级，不否决合法业务终态 |
| 可用性 | 无效或过大的私有详情应降级为有界缺失说明，不能因此阻断合法终态；连接、savepoint 或外层业务事务失败仍按既有失败/重试语义处理，不能伪报保存成功 |
| 查询性能 | 在预先记录的验收环境，20 个并发诊断读请求下，单 Run 详情 p95 ≤ 1 秒、诊断包 p95 ≤ 3 秒 |
| 内容预算 | 单 Run 持久诊断合计 ≤ 128 KiB；下载未压缩总量 ≤ 512 KiB；查询不扫描所有历史事件 |
| 身份安全 | 跨 tenant/workspace/user/Run/Attempt 的混入语料全部被拒绝；管理员读取范围沿用现有管理授权 |
| 数据安全 | 合成敏感值语料在普通接口、管理员接口、诊断包和新增日志中均无泄漏 |
| 可解释性 | 每个标准故障都有证据，或一个准确的缺失原因；不能以缺失原因替代本应实现的 P0 采集 |
| 测试真实性 | 至少一条真实 PostgreSQL 的“异常 → 回调/调和 → 管理查询 → 下载”链路，不能全部靠注入最终 JSON 通过 |

生产指标后续记录：已有 Run 的失败总数、有诊断失败数、可解释缺失数、写入失败数、截断/拒绝分布、导出成功率。指标标签使用受控阶段和原因，Run ID 不进入高基数聚合标签。

## 8. 发布与验收

按技术方案的 S0–S5 实施。S0 先确定契约和源代码迁移权限，后续逐批修复采集与旧路径，再联通页面和导出。每批代码可以独立评审，但 P0 链路、迁移和清理未完成前，不宣称本 PRD 已交付。

最终至少覆盖：模型超时、工具拒绝、HTTP 非成功返回、派发连接中断、异步派发成功后的失败、回调重试、永久调和失败、用户取消竞态、Executor 消失、超长/非法诊断、不同格式版本、跨范围请求、历史 Run。

正式环境验收由持有既有管理权限的人员在页面完成，并关联实际发布包。研发的本地测试和 CI 不能替代该结果；未取得正式环境访问不阻止先完成实现与打包验证。

## 9. 交付完成条件

- PRD-01 至 PRD-14 有对应实现、测试或明确的发布验收记录。
- [技术方案的清理清单](run-diagnostics-design.md#7-硬编码与旧路径处置)全部有逐项处置；仍有已识别真实消费者的兼容项注明拥有者、退出证据和限制。
- 当前契约与运维说明更新到实际行为；历史故障记录保持历史性质。
- 页面和诊断包可解释标准失败，无需运维临时提供容器日志。
- 对数据库不可用、未送达后丢失、历史未采集等限制如实展示。
